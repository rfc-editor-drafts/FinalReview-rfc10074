--- abstract

This document describes a set of Packet CAPture (PCAP) LinkType values and
creates an IANA registry for those values.
These values are used by the PCAP and PCAP Now Generic specifications.

# Introduction

In the late 1980s, Van Jacobson, Steve McCanne, and others at the
Network Research Group at Lawrence Berkeley National Laboratory (LBNL)
developed the tcpdump program to capture and dissect network traces.
The code to capture traffic, using low-level mechanisms in various
operating systems, and to read and write network traces to a file was
later put into a library named libpcap {{LIBPCAP}}.

Other documents describe the original (legacy) file format used by
tcpdump (PCAP {{I-D.ietf-opsawg-pcap}}), as well as a revised file
format {{I-D.ietf-opsawg-pcapng}}, both of which are used by tcpdump
and Wireshark {{Wireshark}}.

Within those file formats, each packet that is captured is indicated by a LinkType value.
The LinkType value selects one of hundreds of formats for metadata and Layer 2 encapsulation of the packet.

This document creates an IANA registry for LinkType values, establishing the IANA
Considerations by which other uses of the PCAP-related formats may register new
LinkType values.

#  IANA Considerations

## PCAP Registry Group {#pcapreg}

IANA has created a new registry group titled "Packet CAPture (PCAP)".

## PCAP-Related LinkTypes Registry {#linktype}

IANA has also created a registry titled "PCAP-Related LinkTypes" within the "Packet CAPture (PCAP)" registry group ({{pcapreg}}).


The registry has the following structure:

* Value: Indicates the 16-bit unsigned integer assigned for this LinkType.
* Name: Indicates the symbolic name for this LinkType. The name is prefixed with "LINKTYPE\_" (i.e., LINKTYPE\_something).
* Description: Provides a very short description.
* Change Controller: As per {{Section 2.3 of !RFC8126}}.
* Reference: Indicates an authoritative document reference for the LinkType or a requester reference.

The allocation policy for the LinkType values is as follows:

* Values from 0 to 65000 are allocated following the Expert Review
 policy ({{Section 4.5 of !RFC8126}}). Values in the ranges
 0-10, 50-51, and 99-301 are already assigned; values in the ranges
 11-49 and 52-98 are reserved and must not be assigned.

* Values from 65001 to 65535 are reserved for Experimental Use ({{Section 4.2 of !RFC8126}}).

The initial contents of the registry are provided in {{sec-initial}}.

The initial contents of the registry are based upon the link-layer header
type list maintained by libpcap and published on {{LINKTYPES}}.

LinkType values 147-162 (named LINKTYPE\_RESERVED\_xx) were originally reserved for Experimental or Private Use, and that continues to be supported.
However, new Private Use cases should use the values in the 65001-65535 range.

In general, Experimental Use values should never leak out of the entity that uses them.
As the Expert Review range is large and easily obtained, official values are recommended.

A LinkType often has an associated Data Link Type (DLT). The numerical value of a given DLT may differ from platform to platform, so while the value for a given LinkType and its associated DLT are often identical, this is not universally so.  DLT values are associated
with specific operating systems, and the numerical values for some of
them are operating system specific and thus are not subject to
standardization.

### Guidance for Designated Experts {#sec-de}

When processing a request for an allocation, the designated expert will encourage the requester to provide a specification at a stable URL.

A specification is not required, but review of the specification often allows the designated expert to determine if the allocation is a duplicate of another specification.

When the contents of the LinkType contain an IPv4 or IPv6 header, the octets between the beginning of the LinkType and the IP header need to be clearly specified.

Specifications that are not publicly available are acceptable.
This includes specifications obtained via liaison agreements (such as specifications or drafts from ITU-T and IEEE), those that may eventually be made public, or those for which no public document will be available.

The minimal requirement is to provide a contact for that LinkType.

For other documents, the designated expert will need to use their judgment or consult the Operations and Management Area Working Group (OPSAWG) or an Area Director.


# Security Considerations

This document describes the IANA registration rules for the LinkType encapsulations.
PCAP-related packet file formats use these values to determine what kind of headers precede network packet captures.
Many of these formats can contain IPv4 and IPv6 packets.
A system reading PCAP-related format captures can be subject to arbitrary inputs that may be controlled by malicious entities, so utmost caution is required.

Many LinkType formats include a "snapshot" length, which may be smaller than the actual packet.  It is therefore very likely that trailing parts of a packet capture may be omitted, yet internal length fields in the packets will claim the packet is bigger than the capture.
This leads to trivial buffer overreads, and systems interpreting the packets need to carefully scrutinize all attempts to read data from a capture.
